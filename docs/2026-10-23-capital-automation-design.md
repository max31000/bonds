## 2. Модель данных (Infrastructure + миграции)

1. **`accounts`**:
   - добавить поля `broker ENUM('tinvest','freedom')` и `base_currency`;
   - новая таблица `broker_credentials` (account_id, kind = `read`|`trade`, encrypted, last4) с шифрованием через DataProtection;
   - токен для торговли читает **только** исполнитель.
2. **Цикл по нескольким счетам.** Планировщик и API перестают брать `GetPrimaryAccountId` и проходят по всем счетам. В интерфейсе появляется выбор счёта или «Все».
3. **Слой `holdings`** — новый, брокеронезависимый:

   | Поле | Пример |
   |---|---|
   | account_id | |
   | instrument_key | ISIN, иначе тикер брокера |
   | asset_class | bond / fund / equity / etf / cash |
   | qty, price, currency | |
   | value_rub, value_usd | |
   | bucket_id | |

   Его собирает каждая синхронизация из позиций T-Invest (облигации, фонды, валюта) и из Freedom. Движок облигаций не трогаем: он по-прежнему работает со своими таблицами по рублёвым облигациям.
4. **`instrument_trading_meta`** (broker, instrument_key, class_code, lot, min_step, currency, api_tradeable, buy/sell_available, venue). Обновляется раз в день. Без неё нельзя правильно посчитать размер заявки.
5. **Freedom-коннектор.**
   - Команды: `getPositionJson`, `getStockQuotesJson`, `getTradesHistory`, `getUserCashFlows`, `GetAllUserTexInfo`, `putTradeOrder`, `delTradeOrder`, `getNotifyOrderJson`.
   - Отдельный маппер операций по образцу `TInvestOperationMapper`.
   - Пополнения и выводы **маппятся** (сейчас bonds их выбрасывает). Они нужны для триггеров «пришли деньги» и для расчёта доходности с учётом пополнений (XIRR).
6. **`target_allocations`** удаляем (BACKLOG:198). Вместо них — таблицы корзин (§3).

## 3. Целевая модель: корзины

Портфель описывается деревом корзин. Параметры корзины:

| Параметр | Значение |
|---|---|
| `target_weight` | доля от всего капитала, дробь |
| `band` | допустимое отклонение по абсолюту, напр. 0.05 |
| `hard_band` | при выходе за неё разрешены продажи |
| `liquidity_tier` | сколько теряем, если продать сегодня: спред плюс типичная просадка цены. 0 — фонды денежного рынка (почти 0); 1 — долговые фонды и ОФЗ (≤ 1–3%); 2 — корпоративные облигации, которые лучше держать до погашения или оферты; 3 — заморожено |
| `broker`, `currency` | |
| `auto_buy`, `auto_sell` | разрешено ли действовать без подтверждения |
| `fill_rule` | как выбирать бумаги внутри: `fixed` — по под-весам; `engine` — через `CashAllocationService` (облигации); `hold` — не докупать |
| `min_trade` | минимальная заявка, ₽ или $ |

**Решения пользователя по рублёвой части:**
- Стратегия — облигации и долговые фонды.
- Акции РФ — не больше 5%, только диверсифицированно.
- Ликвидные деньги (тиры 0–1) — 10–20%.
- Облигации из-за ликвидности не продаём.
- Налог по возможности откладываем — то есть берём фонды **без выплат**.

**Временная корзина.** TPAY и TOFZ@ (≈ 204k, на несколько недель) идут в корзину `temporary`:
- не входит в целевые доли и ребаланс;
- `auto_sell = false`;
- выход по вашей команде `/exit temporary`: план продажи → «доступно к выводу».

Целевая структура (доли — от рублёвой части без временной корзины; правятся в интерфейсе):

| Корзина | Брокер | Цель | Band | Тир | Заполнение |
|---|---|---|---|---|---|
| Ликвидность: фонды денежного рынка и долговые фонды без выплат (TMON@ / LQDT / TSAV / SBFR / TBRU@ по под-весам) | T | 15% (коридор 10–20%) | ±5 п.п. | 0–1 | fixed |
| Прямые облигации (ОФЗ + корпоративные AA–A, по скорингу bonds) | T | 80–85% | ±5 п.п. | 1–2 | engine |
| Акции РФ через широкий индексный фонд | T | 0–5% | ±2 п.п. | 1 | fixed, по умолчанию 0 |
| Временная (TPAY, TOFZ@) | T | вне целей | — | 1 | hold до команды |
| Глобальное ядро (VUAA, SPYM) | F | своя USD-часть | | 1 | fixed + правило $315 |
| Спутники (LUV, UFO, ROBO, SJPA, LGQM, OTGLY) | F | hold | | 2 | hold |
| Заморожено (FNMA, FMCC) | F | hold | | 3 | hold |

Рублёвая и долларовая части ведутся как два самостоятельных портфеля со своими целями. Межброкерских переводов сервис не делает: конвертация 0.4% плюс перевод — это ручное решение.

Отдельно задаются:
- целевая доля по валютам (RUB / USD);
- минимальный остаток денег на каждом брокере.

## 4. Правила (Core/Policy, чистые функции → план)

Все правила выдают **план**: список лимитных заявок с ценой, комиссией, налогом и причиной. Сами правила ничего не исполняют.

- **P1. Парковка кэша (авто).**
  - **Любой** свободный кэш на T-Invest (за вычетом налогов и уже запланированных покупок, порог — цена одного пая) уходит в корзину «Ликвидность» по под-весам. Фонды Т-Капитала — без комиссии.
  - Чужие фонды (LQDT, SBFR) включаются в авто только после того, как первая сделка подтвердит их комиссию.
  - Обратное направление: если плану не хватает денег, сначала продаётся фонд ликвидности.
  - Исполняется в часы основной сессии по Москве — в коде (истина, задача 67) Мосбиржа и СПБ 10:00–18:40 (`Policy:Moex`/`Policy:SpbRu`); исполнитель не выставляет новые заявки и снимает висящие за `Execution:CancelBeforeClose` (10 мин) до закрытия. Цена — mid с округлением до шага цены. Пока действует удержание под вывод (P5), P1 не паркует.
- **P2. Распределение поступлений.**
  - Срабатывает на пополнение (`INPUT`), команду `/inflow N` или погашение облигации.
  - Деньги идут в корзины, которые сильнее всего ниже цели. Внутри корзины бумаги выбираются по её правилу заполнения.
  - Всё сразу паркуется в P1. Покупки облигаций приходят на подтверждение одним планом: облигации имеют спред, а выбор эмитента — это решение.
- **P3. Купоны и амортизация.** Частный случай P2: сразу в корзину «Ликвидность» (авто).
- **P3b. Перелив «Ликвидность → облигации».** Раз в неделю. Срабатывает, если доля ликвидности больше 20% (верх коридора). Правило предлагает план: продать часть фондов и купить облигации из bonds. Облигация попадает в план, только если выполнены оба условия:
  - **выгодно**: доходность к погашению или оферте после налога ≥ ожидаемая доходность фонда после налога + 1.5 п.п. (надбавка за меньшую ликвидность и потерю отсрочки налога);
  - **безопасно**: надёжность «зелёная» по оценке bonds, ликвидность не «Caution», нет флоатеров, рейтинг не ниже A, лимит на эмитента соблюдён. Рейтинг (задача 67) — самый низкий из свежих (≤ 18 мес.) ручных рейтингов эмитента (`issuer_ratings`, ввод на странице эмитента); свежий рейтинг ниже A — бумага не кандидат; свежего рейтинга нет — кандидат допускается (остальные фильтры действуют), в причине строки «рейтинг не указан» (решение владельца T-67D; бесплатного источника рейтингов нет).

  Если кандидатов нет, ничего не делается: «выгодной и безопасной замены нет». Всегда через подтверждение.
- **P4. Ребаланс.**
  - Сначала выравнивание за счёт новых денег, без продаж.
  - Продажи предлагаются, только если корзина вышла за `hard_band`. Всегда через подтверждение. Флаг `auto_sell` корзины на P4 не влияет (задача 67: он только про авто-исполнение, а P4 всегда ждёт решения); корзины `hold` не трогаются.
- **P5. Вывод (`/withdraw 15%` или `/withdraw 50000`).**
  - Продажи в порядке тиров: 0 → 1 → 2.
  - Внутри тира — в порядке наименьшего налога: сначала позиции с убытком, потом с минимальной прибылью; бумаги, которым до льготы ЛДВ осталось немного, — в конец.
  - План показывает сумму к выводу после налога и комиссии. После исполнения бот сообщает: «доступно к выводу N ₽» (через `GetWithdrawLimits`).
  - Сам вывод вы делаете вручную: в API его нет. Поэтому сумма к выводу удерживается (`summary.cashHold`): пока план открыт и `Policy:WithdrawHoldTtl` (3) рабочих дня после исполнения, либо до `/withdrawn` / «Деньги выведены». Вывод целиком из свободных денег — план «только удержание» без строк: подтверждение сразу делает его `Done` (задача 67).
  - По Freedom: вывод стоит минимум $20, поэтому правило предупреждает, если выводимая сумма меньше ~$1000.
- **P6. События** (из существующих сигналов bonds):
  - Put-оферта: напоминание и план (подать оферту через API нельзя — это ручное действие).
  - `IssuerDefaultEvent`: срочное уведомление.
  - `ConcentrationLimitBreached`: план на подтверждение.
  - Ценовые и календарные триггеры по спутникам (OTGLY — релиз «Ведьмака 4» или отчёт).
- **P7. Доливки Freedom.** До ~$315 — SPYM.US (через ITS, 0.5%), иначе VUAA.EU. В плане `.ITS`-тикеры запрещены.
- **P8. Налоги** — отложено («в долгий ящик»). В первой версии остаётся только то, что нужно правилам:
  - FIFO-стоимость лотов, чтобы оценить налог при продаже в P5;
  - выбор фондов без выплат в P1.

## 5. Исполнение и безопасность (Infrastructure/Execution)

**Жизненный цикл плана.** `Draft → AutoApproved | PendingApproval → Approved → Submitting → (PartiallyFilled) → Done | Expired | Rejected | Failed`.

**Хранение.**
- Таблицы `trade_plans` и `trade_orders`.
- `client_order_id = plan:line:attempt` — это идемпотентность: после перезапуска заявка не отправится повторно.

**Жёсткие лимиты.** Хранятся в конфиге и env, а не в БД, которую видят агенты:

| Лимит | По умолчанию |
|---|---|
| **Автоисполнение (без вопроса)**: на одну заявку | 25 000 ₽ |
| **Автоисполнение**: в день | 50 000 ₽; Freedom — $0, только с подтверждением |
| Белый список для авто | только фонды корзины «Ликвидность» |
| **С подтверждением** | лимитов по сумме нет. Остаются отклонение от mid, часы торгов и проверка, что хватает денег |
| Отклонение цены от mid | фонды 0.2%, облигации 0.5% |

- Заявки только лимитные, без маржи, только в часы торгов, с учётом календаря праздников Мосбиржи.
- Аварийный выключатель: `/stop` в Telegram и настройка `execution_enabled`.

**Перевыставление.** Если заявка не исполнилась за N минут, цена сдвигается к противоположной стороне стакана, но не дальше лимита отклонения. Максимум K попыток. После этого — `Expired` и уведомление.

**Сверка после исполнения.**
- Повторная синхронизация.
- Сравнение списанной комиссии с моделью: если разница больше 0.01 (абсолютной), приходит тревога.

**Telegram.**
- Опрос `getUpdates` в фоновом сервисе (публичный webhook не нужен).
- Inline-кнопки «Да / Нет / Детали», в callback — plan_id и одноразовый nonce.
- Принимаются сообщения любого зарегистрированного пользователя (Telegram id в `users`), каждый управляет только СВОИМИ планами; незнакомые id — «Нет доступа». Это поправка §11 (мультипользовательность, без «владельца»), код — истина (задача 67). Команды — только в личном чате с ботом.
- Подтверждение истекает через 30 минут или раньше, если цена ушла дальше лимита отклонения.

**Токены.**
- T-Invest: полный доступ, **на один счёт**, используется только для торговли.
- Freedom: отдельная серверная пара ключей.

**Запуск.**
1. **2 недели dry-run**: планы строятся и приходят в Telegram с пометкой «сделка не отправлена».
2. Затем включается T-Invest: сначала только P1.
3. Потом Freedom.

**Тесты.**
- Unit — правила как чистые функции с эталонными случаями (как `PositionIncomeCalculatorTests`).
- Integration — песочница T-Invest для исполнителя. У Freedom песочницы нет, поэтому для него mock плюс dry-run.

## 6. Агенты (фаза 2)

**Запуск.**
- Claude Code CLI в контейнере на VDS, режим `claude -p` (без интерактива).
- Вызывает планировщик: ежедневный дайджест, события сигналов, ежемесячный обзор.

**Доступ.**
- **Read-only MCP bonds**: портфель, корзины, сигналы, денежные потоки, оценки надёжности, котировки, движения денег.
- Поиск в интернете.
- Единственный инструмент записи — `propose_plan`. Он создаёт план с `source=agent` и **всегда** в статусе `PendingApproval`.
- Лимиты, токены и `execution_enabled` агенту недоступны.

**Задачи.**
- Новости и отчётность эмитентов облигаций (GIR BO), разбор оферт.
- Триггер по OTGLY.
- Объяснение планов «почему так».
- Ежемесячный обзор: дрейф корзин, комиссии против модели, налоговый календарь.

**Вывод.** Заметки сохраняются в `agent_notes` и уходят в Telegram.

**Расход.** Лимит на один запуск; Sonnet/Haiku для рутины, Opus — для ежемесячного обзора.

**Авторизация.**
- `claude setup-token` на вашей машине выдаёт OAuth-токен подписки, он действует 1 год. В контейнер он идёт через env `CLAUDE_CODE_OAUTH_TOKEN` (`/etc/mvv42/env/<container>.env`, права 600).
- В контейнере **не должно быть** `ANTHROPIC_API_KEY`: при наличии ключа `-p` берёт его и списывает деньги с API-счёта.
- Не использовать флаг `--bare`: он игнорирует OAuth-токен.
- Условия: документация описывает setup-token «для CI и скриптов». Для сервисов, которыми пользуются другие люди, Anthropic направляет к API-ключу. Личный сервис для одного владельца — это ваш собственный сценарий; при сомнениях — API-ключ с `--max-budget-usd`.

**Запуск.**
```
claude -p "<задача>" --output-format json --strict-mcp-config --mcp-config /app/agent-mcp.json \
  --tools "Read" --allowedTools "mcp__bonds__*" --permission-prompts none --max-turns 30
```
- Веб-поиск включается отдельно для исследовательских задач.
- Результат и `total_cost_usd` пишутся в `agent_notes`. Ненулевой код выхода — сбой и тревога в Telegram.

Источники: code.claude.com/docs/en/authentication, /headless, /cli-reference, /mcp.

## 7. Фазы

1. **Мультиброкерное чтение.** Freedom-коннектор, `holdings`, метаданные для торговли, маппинг пополнений и выводов, выбор счёта. Без сделок.
2. **Корзины и правила.** Корзины, P1–P7, планы, Telegram с кнопками в режиме dry-run.
3. **Исполнитель T-Invest.** Полный токен на один счёт, лимиты, перевыставление, сверка. Сначала только P1, затем остальное с подтверждением.
4. **Исполнитель Freedom.**
5. **Агенты.**
- Налоги (P8) — отложено.

Каждая фаза — отдельная спецификация и план в `bonds/plan/`.

## 8. Риски

- **Ошибка в данных превращается в сделку.** Защита: лимиты, dry-run, отклонение от mid, сверка после исполнения.
- **Брокер меняет API или тариф.** Защита: сверка комиссий и `api_tradeable` из метаданных.
- **Неправильная маршрутизация `.US` → ITS.** Защита: комиссия в плане считается по фактическому маршруту из прошлых сделок, а после исполнения сверяется.
- **Утечка токена для торговли.** Защита: токен на один счёт, шифрование, токен не попадает в логи и агентам.

## 9. Решения (23.10.2026)

1. **Структура РФ.** Облигации и долговые фонды. Акции РФ ≤ 5%, через широкий фонд, по умолчанию 0. TPAY и TOFZ@ — временная корзина на несколько недель.
2. **Ликвидность.** После выхода из временной корзины — коридор 10–20%, цель 15%. Облигации ради ликвидности не продаём; купоны идут в фонды; излишек сверх коридора переливается в облигации по правилу P3b.
3. **Фонды для парковки.** Только долговые или денежного рынка и **без выплат** — налог откладывается. Можно делить по под-весам. Фонды Т-Капитала — 0% комиссии.
4. **TPAY.** После выхода из временной корзины замена на фонды без выплат (например SBFR — те же флоатеры) — по правилу P1, решение уже принято.
5. **Автоисполнение без вопроса.** 25k ₽ на заявку, 50k ₽ в день, только фонды ликвидности. С подтверждением — без лимитов по сумме.
6. **Парковка.** Любой кэш, сразу.
7. **Порядок продаж при выводе.** Как в P5.
8. **Telegram.** Один общий бот bonds.
9. **Dry-run 2 недели** — да.
10. **Агенты.** OAuth-токен подписки (`claude setup-token`) — см. §6.
11. **Торговый токен T-Invest.** Выпускается к фазе 3.
12. **Налоговый модуль** — отложен.
13. **Сервер.** Ресурсов достаточно. При необходимости — доступ по SSH и мониторинг в админке.
14. **Документы.** Спецификация лежит в `bonds/docs/`, планы — в `bonds/plan/NN-*.md`. `target_allocations` удаляется.

## 10. Открытые моменты (проверить по ходу, не блокируют фазу 1)

- **Комиссия чужих фондов на premium** (LQDT, SBFR, SBRB). Проверить первой мелкой сделкой.
- **ЛДВ для паёв российских фондов** через 3 года. Если подтвердится, фонды без выплат становятся ещё выгоднее.

## 11. Поправка 23.10.2026: подключения на пользователя, ИИ-провайдер не хардкодится

- Все секреты задаются **пользователем в настройках** («Подключения»): T-Invest read, T-Invest trade, Freedom (public/private), ИИ-провайдер. Каждый включает свою часть функционала, без секрета эта часть скрыта (`/api/capabilities`). Хранение — единая таблица `user_credentials` + реестр провайдеров в коде. Новый брокер или ИИ-провайдер добавляется записью в реестре и валидатором, без миграций (задача 58).
- **ИИ-агенты опциональны.** Первый провайдер — `claude_code`: OAuth-токен подписки из `claude setup-token`, **не API-ключ**. Раннер агентов (фаза 5) работает через интерфейс `IAgentRunner`, OpenAI и другие провайдеры добавляются реализацией этого интерфейса. В контейнере агента нет `ANTHROPIC_API_KEY` — иначе спишутся деньги с API. Токен пользователя подставляется в env процесса `claude -p` на время одного запуска.
- **Мультипользовательность.** Новый код всегда работает по `user_id`, без «владельца». Фоновые задачи проходят по всем пользователям, у которых есть нужное подключение. Допуск друзей в авторизацию (сейчас пускается только OwnerId) — отдельная задача, когда понадобится.
- **Управление** — веб-интерфейс (корзины, правила, планы) и Telegram-бот (подтверждения и ситуативные команды `/withdraw`, `/inflow`, `/status`, `/stop`).
