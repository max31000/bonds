## Проблема

Прод-баг 2026-10: ОФЗ 26226 погасилась, а сервис продолжал считать её в итогах. Корень в синке
закрыт, но аудит нашёл, что журнальные/исторические расчёты тоже не умеют погашения и
переводы бумаг: история стоимости, XIRR и P&L врут у любого клиента, у которого раз в год что-то
гасится, амортизируется или переводится.

## Что сделать

1. **История (B1).** `PortfolioHistoryRebuildService.ApplyOperation` (~:150–165) меняет
   количество только на Buy/Sell. Redemption (полное погашение) → количество инструмента = 0;
   вывод бумаг → минус количество; ввод → плюс. Цена инструмента НЕ forward-fill'ится позже
   `instrument.MaturityDate`. Тест: бумага куплена, погашена; чекпойнты после погашения не
   содержат её стоимости.
2. **Снапшот «сейчас» и XIRR (B2).** `PortfolioSnapshotService` (:48–73): исключать из market
   value позиции с `MaturityDate < asOf` (у брокера бумага может провисеть день-два после даты
   погашения до выплаты — тогда в стоимость идёт НОМИНАЛ остатка, а не последняя котировка; если
   в журнале по инструменту уже есть Redemption — стоимость 0). Тест на отсутствие двойного учёта
   (приток Redemption + терминальная стоимость той же бумаги).
3. **Ремонт данных.** Уже сохранённые снапшоты в проде содержат призрак ОФЗ 26226. Нужен
   одноразовый пересчёт: миграция `015_*.sql` (следующий номер; обновить
   `MigrationIdempotencyTests` — число + список), которая удаляет `portfolio_value_snapshots`,
   так что существующий бэкфилл (`PortfolioHistoryBackfillService`, запуск в
   `SyncSchedulerHostedService` ~:168) пересоберёт историю. ПРОВЕРЬ по коду, что бэкфилл
   действительно стартует при пустой таблице и пересобирает всю историю; если нет — сделай так,
   чтобы стартовал (без ручных действий владельца).
4. **Не-облигационные операции (B3).** `TInvestOperationMapper`/`BondSyncService` (~:92–113):
   Buy/Sell/Coupon по акциям, фондам, валюте (CNYRUB_TOM и т.п.) попадают в журнал с
   `InstrumentId = null` и портят XIRR/InvestedRub. Пробросить `InstrumentType` из
   `OperationItem` в `TInvestOperation`; Buy/Sell/Coupon/Redemption/Amortization сохранять только
   для `bond`. Fee/Tax без инструмента — как сейчас. Пополнения/выводы денег — проверь, как
   сейчас маппятся и используются в XIRR (XIRR по счёту должен их учитывать как внешние потоки
   ЛИБО считаться по облигационным потокам — выбери согласованно с текущей формулой, задокументируй).
5. **Инструменты для исторических операций (M6).** Для операции с FIGI облигации, которой нет в
   справочнике (куплена и погашена/продана до первого синка) — создавать инструмент тем же
   `ResolveOrCreateInstrumentAsync` (+ `EnrichFromMoexAsync` по возможности), чтобы
   `InstrumentId` не был null. Кэшировать резолв в пределах синка (не N запросов на один FIGI).
6. **Переводы бумаг (M3).** Замапить `InputSecurities`/`OutputSecurities` (и проверь реальные
   имена enum в SDK `Tinkoff.InvestApi` — `OperationType`) в новые типы операций
   `SecurityIn`/`SecurityOut` (ENUM в `operations.type` — миграцией, если колонка ENUM). Для XIRR:
   ввод бумаг = внешний приток капитала по рыночной стоимости на дату (если цены нет — исключить
   и пометить), вывод — симметрично. Cost basis: ввод без цены → `HasUnknownLots` (как сейчас).
7. **Амортизация в cost basis (M1).** `PositionCostBasisService` (:51–55, :97–123): Amortization —
   возврат капитала: уменьшает вложенное (`runningCost -= amount`), количество не меняется.
   Тест с эталонными числами руками: 10 бумаг × 1000 куплены по 1000, амортизация 30% (3000 ₽) →
   invested 7000, market value при цене 100% = 7000, P&L 0 (а не −3000).
8. **Налог на купоны (M2).** Проверь по `TInvestOperationMapper`, как маппятся
   `BondTax`/`BondTaxProgressive`/`Tax*` с FIGI. «Купонов получено» в cost basis — нетто:
   вычитать налоговые операции того же инструмента. Поправить doc-comment, который утверждает,
   что брокер платит нетто, если это не так.
9. **Котировки погашенных/делистингованных (M8).** `BondSyncService` fallback-котировка
   (`GetQuotesAsync`) — не писать для инструмента с `MaturityDate < today`. Даты котировок —
   `BusinessClock.MoscowToday()` вместо `DateOnly.FromDateTime(DateTime.UtcNow)` во всём
   `BondSyncService` (BACKLOG техдолг — закрыть).
10. **Поступления сегодняшнего дня (m4).** `BondCashFlowBuilder`/проекция берут потоки строго
    `> asOf` — выплата в день погашения/купона пропадает из «Ближайших поступлений» до факта.
    Включить `>= asOf` для отображения (проверь, что это не задваивает XIRR/доходности — у
    доходностей горизонт свой).

Тесты: юнит на каждый пункт (эталонные числа руками), интеграционный — минимум миграция.

## Критерии приёмки

- [ ] Погашенная бумага не участвует ни в одной «текущей» стоимости, ни в истории после даты погашения.
- [ ] XIRR не учитывает погашение дважды; покупки валюты/акций не попадают в облигационный XIRR.
- [ ] Амортизация не создаёт фиктивный убыток в P&L; «купонов получено» — нетто налога.
- [ ] После деплоя история стоимости пересобирается автоматически (миграция 015 + бэкфилл).
- [ ] Существующие тесты не ослаблены; `scripts/pre-push-check.sh --all` — зелёный.
