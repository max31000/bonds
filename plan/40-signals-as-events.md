## Проблема

У владельца ~1100 сигналов — вкладка бесполезна. Причины (аудит, файл:строка):
- `signals` — append-only лог: `SignalRepository` умеет только Create/MarkRead, ничего не
  закрывается и не удаляется.
- Ключ дедупа `SignalDeduplicator.cs:48` включает `Date`; четыре правила ставят `Date = AsOf`
  (`YieldBelowAlternativeRule` :287, `ConcentrationLimitRule` :331, `UninvestedCashRule` :244,
  `DurationDriftRule` :371) → копия того же состояния КАЖДЫЙ синк (2+ раза в день + автосинк).
  `YieldBelowAlternative` — на каждую позицию каждый день: основной объём.
- Дедуп смотрит только непрочитанные (`SyncCycleService.cs:259`) → «прочитано» воскрешается.
- `YieldBelowAlternativeRule` сравнивает доходность флоатеров с YTM фиксов (нарушает
  `ReplacementMatrixService.IsComparable`) и дублирует «слабые позиции» Рекомендаций.
- `FloaterRateResetRule` (:162–190) срабатывает на фикс-бумаги с офертой (BACKLOG техдолг).
- `UninvestedCashRule` — прокси по журналу, не реальный остаток; `DurationDriftRule` мёртв
  (`target_allocations` никто не пишет); `LowLiquidityWarningRule` — заглушка.
- Пороги со страницы Настроек (`UserSettings`) движок не читает — только `IOptions<SignalEngineOptions>`.
- Фронт: `types.ts:356` severity `'Low'|'Medium'|'High'`, а бэк шлёт `Info|Warning|Critical`;
  `TYPE_LABEL` в `Signals.tsx:29–40` не совпадает с enum бэка (`UpcomingCoupon` …); карточки
  показывают «позиция #id» вместо имени. Тесты фронта используют выдуманные значения.

## Что сделать

### A. Backend: события как «текущее состояние»

1. Каждый цикл движок пересчитывает ПОЛНЫЙ набор активных событий; ключ события —
   `(type, instrument_id|issuer, event_date)` где `event_date` = дата события (оферты, погашения,
   ресета), а для состояний (концентрация) — NULL. Хранение: новая таблица (миграция, следующий
   номер; обновить `MigrationIdempotencyTests`) с `UNIQUE KEY` по ключу, полями severity,
   payload/текстом, `first_seen_at`, `last_seen_at`, `resolved_at NULL`, `acknowledged_at NULL`;
   либо переделка `signals` — на твой выбор, но старые ~1100 строк удалить в миграции.
   Синхронизация: новый ключ → insert; существующий → bump `last_seen_at` (+обновить текст/
   severity); ключ больше не производится → `resolved_at = now`. «Прочитано»/ack никогда не
   воскрешается. Чистка resolved старше 90 дней — в том же цикле.
2. Правила (только по ОТКРЫТЫМ позициям; используй `PortfolioHoldingsBuilder` вместо копии
   сборки холдингов в `SyncCycleService.RunSignalsAsync` :265–339):
   - put-оферта в окне N дней (Critical) — требует решения владельца;
   - call-оферта (Warning);
   - погашение в окне (Info) и амортизация (Info);
   - пересмотр ставки ТОЛЬКО для настоящих флоатеров (`CouponType.Floating`; фикс с офертой — нет);
   - концентрация по эмитенту > лимита (Warning, состояние);
   - свободные деньги > порога (Info, состояние) — по `accounts.cash_rub`, не по прокси журнала.
   Удалить: `YieldBelowAlternative`, `UpcomingCoupon` (купоны — это календарь, он уже есть на
   «Денежном потоке» и дашборде), `DurationDrift`, `LowLiquidityWarning` + связанные настройки/
   опции/DTO-поля и UI-поля в Настройках, которые после этого ничего не делают.
3. Пороги (окно дней, лимит концентрации, порог кэша) — из `UserSettings` с дефолтами из
   options (как делает Analytics, `AnalyticsEndpoints.cs:~1250`).
4. API: `GET /api/signals` по умолчанию — активные (не resolved), с именем бумаги/эмитента,
   датой события, severity строкой как в enum бэка; `?include=resolved` — история. Ack —
   существующий эндпоинт пометки прочитанным (сохранить маршрут, если фронт его зовёт) + «всё
   прочитано».
5. Тесты: юнит на синхронизацию набора (новое/существующее/исчезнувшее/ack не воскрешается),
   на каждое правило (фикс с офертой не даёт ресет, погашенная позиция ничего не даёт),
   интеграционный на эндпоинт.
6. Telegram: при появлении НОВОГО Critical события (put-оферта) — одно сообщение через
   существующий `ITelegramAlertSender` (с троттлингом как у `SyncAlertThrottle`), без купонов.

### B. Frontend

1. Вкладку «Сигналы» переименовать в «События». Типы в `api/types.ts` — буквально как DTO бэка.
2. Список активных, сгруппированный по severity → дата события; на карточке имя бумаги, дата,
   что сделать («решить до …», «кандидат на…» — формулировки «оценка/кандидат», не «купите»);
   кнопки «прочитано» и «всё прочитано»; свёрнутая «История». Пустое состояние —
   «Ничего не требует внимания».
3. KPI на дашборде — число активных непрочитанных Critical+Warning (не всех).
4. Vitest: реальные enum-значения бэка в фикстурах, группировка, пустое состояние, ack.

## Критерии приёмки

- [ ] На портфеле владельца после деплоя — единицы активных событий, не сотни; повторный синк
      не создаёт дублей; ack не воскрешается.
- [ ] Ни одного события по погашенным/проданным бумагам; ресет ставки только у флоатеров.
- [ ] Пороги со страницы Настроек реально влияют; мёртвые настройки убраны.
- [ ] Severity/типы на фронте отображаются по-русски (нет сырых enum-имён).
- [ ] `scripts/pre-push-check.sh --all` — зелёный.
