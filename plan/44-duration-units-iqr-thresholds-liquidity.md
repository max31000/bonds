## Проблема

Три дефекта корректности текущей модели (по коду main a89dba0):

1. **Смешаны дюрации.** Бакет позиции в RV считается по **модифицированной** дюрации
   (`ReplacementEndpoints.cs` ~274, 538), а члены корзины банка — по **Маколею**
   (MOEX DURATION/365). Позиция у границы бакета попадает не в свою корзину. Фронтовый фильтр
   «похожая дюрация ±1.5 г.» (`bonds-web/src/pages/Recommendations.tsx` ~53, 268–271) сравнивает
   `candidate.durationYears` (Маколей) с `modifiedDuration` позиции.
2. **Абсолютный порог 20 б.п. на всё.** Вердикт Cheap/Fair/Rich — `|dev| < 0.0020`
   (`ReplacementEndpoints.cs` ~310–314). P25/P75 корзины считаются (`RelativeValueService`),
   но нигде не используются; Confidence (размер корзины) только отображается. В узкой корзине
   20 б.п. — много, в широкой ВДО-корзине — шум.
3. **Ликвидность зависит от времени суток и наличия стакана.** `LiquidityScoreCalculator`
   присваивает High/Medium только при известном bid/offer; null → Low → Caution → Red даже у
   бумаги с оборотом в сотни миллионов. TurnoverRub = VALTODAY «на сейчас»: утром мал.

## Что сделать

### A. Одна дюрация в сравнении с банком — Маколей

1. Везде, где позиция сопоставляется с корзиной/банком (`ReplacementEndpoints`: бакет позиции,
   пустой список при отсутствии дюрации; RV-эндпоинт), использовать **Маколея** из движка
   (`BondMetrics`), не ModifiedDuration. Doc-comment: «банк хранит MOEX DURATION = Маколей».
2. DTO позиций для этих экранов: добавить `macaulayDurationYears` (additive; ModifiedDuration
   не убирать — он остаётся мерой чувствительности в своих местах: сценарии ставок, PVBP).
3. Фронт: фильтр «похожая дюрация» и подписи сравнивают Маколея с Маколеем
   (`Recommendations.tsx`, `positionsShared.tsx` при необходимости); удалить устаревший
   комментарий со ссылкой на `ReplacementMatrixService`.

### B. Порог вердикта RV от IQR корзины + Confidence как гейт

1. В `RelativeValueService` (или потребителе вердикта) заменить абсолютный порог:
   - `IQR = P75 − P25` корзины (уже считаются);
   - порог: `threshold = max(SpreadThresholds.DeviationFraction, 0.25 × IQR)`;
   - вердикт: `dev > +threshold` → Cheap; `dev < −threshold` → Rich; иначе Fair.
   `SpreadThresholds.DeviationFraction` (0.0020) остаётся нижней планкой и единственной
   константой; множитель 0.25 — именованная константа рядом с ней с doc-comment
   «эвристика до калибровки на истории (BACKLOG О2)».
2. Confidence гейтит вердикт: при Confidence == Low (fallback «весь рынок») вердикт не
   Cheap/Rich, а новый статус `InsufficientData` («мало сопоставимых бумаг») — и в DTO, и в UI
   бейджем. Confidence Medium (весь сектор) — вердикт выдаётся, бейдж «по сектору».
3. Ось спреда светофора (`CandidateRiskSignalService.AssessSpread`) использует тот же
   `threshold` вместо голого 0.0020 (матрицу агрегации не менять — см. рамки).

### C. Ликвидность: скользящий оборот, стакан без данных ≠ Red

1. `LiquidityScoreCalculator`: оборот — **медиана turnover_rub за последние 5 торговых дней** из
   `bond_universe_history` (есть с задачи 42) с fallback на сегодняшний VALTODAY, если истории
   нет. Прокинуть медиану в вызывающие места (universe-эндпоинт, RV-корпус, кандидаты) без N+1 —
   одним запросом по всем secid (образец — существующие батчевые чтения истории).
2. Отсутствие bid/offer при живом обороте больше не даёт Low:
   - High: медиана оборота > 5 млн **и** спред стакана известен **и** < 0.3%;
   - Medium: медиана > 300 тыс. **и** (спред < 1.5% **или спред неизвестен**);
   - Low: медиана > 0 или есть сделки/стакан;
   - None: всё null. Пороги — те же константы, помеченные «не откалиброваны».
3. В `CandidateRiskSignals.Liquidity` подпись различает «тонкий стакан 2.1%» и «стакан не виден
   в снимке» (для UI-тултипа).

### Тесты

- Юнит: бакет по Маколею (эталон: Маколей 3.1 / Modified 2.8 у границы 3 лет → бакет 3–5);
  IQR-порог (узкая корзина IQR=10 б.п. → порог 20 б.п.; широкая IQR=200 б.п. → порог 50 б.п.;
  эталонные числа руками); Confidence Low → InsufficientData; ликвидность: оборот 300 млн +
  bid/offer null → Medium (не Low); медиана из истории против сегодняшнего VALTODAY.
- Vitest: фильтр дюрации сравнивает маколеевские значения; бейдж InsufficientData рендерится.
