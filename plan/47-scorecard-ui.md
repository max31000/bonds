## Проблема

Скоркарта (задача 46) ценна только если решение можно принять «понятно, быстро и прозрачно»:
один взгляд — балл и светофор, один клик — из чего балл сложился и каких данных не хватает.
Сейчас светофор — точка без объяснения, а «дешевизна» выглядит как риск. Нужно развести оси:
надёжность (Risk) и дорогая/дешёвая (Value).

## Что сделать

### A. Компонент разбивки скоркарты

1. `components/ReliabilityScoreCard.tsx`: шапка — светофор + `score` (крупно) + `coverage`
   («данных: 78%»); критические флаги — красными бейджами с человекочитаемыми подписями
   (словарь key→текст в этом же файле); тело — таблица компонентов по слоям
   (Структура выпуска / Отчётность эмитента / Рынок): название, значение (`rawDisplay`),
   баллы `points/maxPoints`, источник (MOEX / ГИР БО / Т-Инвест / вручную / история торгов).
   `missing` — серая строка «нет данных» (+ `Stale` — жёлтая пометка «отчётность устарела»).
   Дисклеймер «оценка, не кредитный рейтинг и не рекомендация» (`components/Disclaimer.tsx` или
   текстом в подвале карточки).
2. Переиспользование: существующий бейдж светофора (T-38) остаётся точкой входа — клик/тап
   открывает `ReliabilityScoreCard` в `Popover` (desktop) / `Drawer` (mobile, `useMediaQuery` по
   паттерну `PositionCard`).

### B. Разведение Risk и Value на страницах

1. Везде, где сейчас светофор (Рекомендации блок 1/2, Скринер, карточка позиции,
   сравнивалка): рядом два независимых бейджа — светофор (Risk) и value-бейдж
   Cheap/Fair/Rich/«мало данных» (`valueVerdict`; переиспользовать/обобщить
   `RelativeValueBadge`, добавить состояние InsufficientData из задачи 44).
2. Тултип value-бейджа объясняет: «G-спред X б.п. против медианы корзины Y б.п. (порог ±Z)»;
   тултип светофора — «балл N из 100, подробности по клику».
3. `PositionDetail`: секция «Надёжность» с развёрнутой `ReliabilityScoreCard` (не попап) +
   формы ручного ввода (см. C).
4. Фильтр «только 🟢» и `reliability=`-параметры продолжают работать без изменений.

### C. Формы ручного ввода (эндпоинты из задачи 46)

1. На `PositionDetail` (секция «Надёжность») и на странице Настроек — блок «Данные эмитента»:
   - рейтинг: агентство (селект АКРА/Эксперт РА/НКР/НРА/другое), рейтинг (строка), дата, заметка;
     список текущих с удалением;
   - ручная отчётность: год + 4–6 ключевых полей (выручка, опер. прибыль, проценты к уплате,
     капитал, долг кратк./долгосрочн.) — для банков/скрытых эмитентов; подпись «₽, как в
     консолидированной отчётности».
2. UX: формы видны всегда, но свёрнуты; после сохранения — рефетч скоркарты; ошибки 422 —
   `ErrorState`/инлайн.

### Тесты (vitest + MSW)

- `ReliabilityScoreCard`: рендер компонентов по слоям, Missing-строки, критические флаги,
  coverage; раскрытие через Popover (ассерты видимости ПОСЛЕ раскрытия — правило гайда).
- Риск- и value-бейджи рендерятся независимо (Red+Cheap одновременно — кейс из мотивации цикла).
- Форма рейтинга: сабмит → MSW-хендлер → рефетч; валидационная ошибка.
- Даты в тестах — относительные (правило гайда).

## Критерии приёмки

- [ ] С любого экрана с бумагой за ≤2 клика видно: балл, покрытие данными, все компоненты с
      источниками, чего не хватает.
- [ ] Risk и Value — два независимых бейджа; «дешёвая + зелёная» бумага отображается именно так.
- [ ] Ручной рейтинг/отчётность вводятся с фронта и сразу влияют на показанный балл.
- [ ] Мобильная вёрстка (375px) карточки скоркарты — Drawer, без горизонтального скролла.
- [ ] `scripts/pre-push-check.sh --all` — зелёный (включая typecheck).
