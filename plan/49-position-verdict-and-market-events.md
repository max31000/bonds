## Проблема

Решение «держать / докупить / менять / фиксировать» сейчас собирается вручную из разных
экранов: светофор на одном, RV-вердикт на другом, выгода замены на третьем, события — только
календарные (оферта/погашение/амортизация/пересчёт/концентрация/кэш). Рыночных и кредитных
событий нет вовсе: расширение спреда позиции, падение цены, свежий дефолт/техдефолт эмитента
система не замечает — хотя все данные для этого уже есть (история банка 42, флаги 43,
скоркарта 46).

## Что сделать

### A. Вердикт позиции (Bonds.Core, чистый сервис)

1. `Bonds.Core/Analytics/PositionVerdictService.cs`: вход — по позиции: `ReliabilityScore`
   (46), value-вердикт RV (44), активные события позиции, результат лучшей замены
   (`NetBenefitAfterTax`, `AnnualizedBenefitFraction` из 48, может быть null), лимит
   концентрации. Выход `PositionVerdict`:
   `Verdict` enum: `Hold | BuyMoreCandidate | ConsiderReplace | ConsiderExit` +
   `Reasons: string[]` (топ-3, человекочитаемые) + `Confidence` (по Coverage скоркарты).
2. Правила (порядок важен, первое сработавшее; все пороги — именованные константы):
   - критические флаги скоркарты (`IssuerDefaulted`, `InterestUncovered`, `NegativeEquity`,
     `SpreadShock`) или Red → `ConsiderExit`, причины из флагов;
   - Red нет, но есть замена с `AnnualizedBenefitFraction ≥ 0.005` (50 б.п. годовых после
     налогов и издержек) **и** светофор цели не хуже hold → `ConsiderReplace` с цифрой выгоды;
   - Green + value=Cheap + концентрация эмитента после докупки ≤ лимита → `BuyMoreCandidate`
     («дёшево к корзине при здоровом эмитенте; впишется в лимит»);
   - иначе `Hold` (причина: «в рамках корзины, выгодных замен после издержек нет»).
   Флоатеры: `ConsiderReplace` по выгоде не предлагать (несравнимые доходности, правило
   `YieldComparability`), остальные правила работают.
3. Эндпоинт: `GET /api/analytics/position-verdicts` (все позиции разом, батчево; лучшая замена —
   переиспользовать выборку кандидатов `mode=rv` с лимитом 3 и прогон через
   `SwitchAnalysisService` v2; без N+1 — собрать входы заранее).
4. Юнит-тесты: по кейсу на каждое правило + приоритет (Red бьёт выгодную замену), флоатер,
   позиция без скоркарты (Coverage 0 → Hold с Confidence Low и причиной «мало данных»).

### B. Новые события (SignalsEngine)

Добавить три правила по образцу существующих (state-based, EventKey, severity; пороги — в
`SignalEngineOptions`, переопределяемые из user_settings; все — только по позициям Quantity > 0):

1. `SpreadWidening` (**Warning**): effective G-спред бумаги сегодня − его медиана за 20 торговых
   дней > `SpreadWideningThresholdFraction = 0.0050` (50 б.п.). EventKey по ISIN + неделя ISO
   (чтобы событие не мигало день-к-дню). Источник — `bond_universe_history`; < 10 дней истории —
   не генерировать. Для бумаги вне банка (неторгуемая) — пропуск.
2. `PriceDrawdown` (**Warning**): чистая цена (price_percent) ниже максимума за 20 торговых дней
   более чем на `PriceDrawdownThresholdFraction = 0.05`. EventKey — ISIN + неделя.
3. `IssuerDefaultEvent` (**Critical**): у любой бумаги эмитента позиции в `security_details`
   появился `has_default=1` или `has_technical_default=1`. EventKey — emitent_id + тип
   (дефолт/техдефолт): событие живёт, пока флаг есть; Telegram-алерт на Critical уже
   подключён — проверить, что новое событие в него попадает.
4. `SignalEvaluationInput` расширить необходимыми данными (история, дефолт-агрегат) — собирать
   в `SyncCycleService` батчево. Тесты: по правилу на кейс (есть/нет истории, порог ровно на
   границе, неделя-ключ стабилен внутри недели).

### C. Frontend

1. Страница Позиций и `PositionDetail`: бейдж вердикта (нейтральные цвета: Hold — серый,
   BuyMoreCandidate — синий, ConsiderReplace — жёлтый, ConsiderExit — красный) + тултип с
   причинами; на `PositionDetail` — блок «Вердикт» с причинами списком, Confidence и
   дисклеймером «оценка, не рекомендация»; ссылка «подобрать замену» ведёт на Рекомендации с
   выбранной позицией (существующий роутинг).
2. Страница «События»: новые типы с иконками/подписями; фильтры не ломать.
3. Vitest: рендер вердиктов всех четырёх типов; новые события в списке; тултип причин.

## Критерии приёмки

- [ ] У каждой позиции виден вердикт с ≤3 причинами словами; Red-бумага — `ConsiderExit`,
      дешёвая зелёная в рамках лимита — `BuyMoreCandidate` (интеграционные тесты).
- [ ] Расширение спреда позиции на 50+ б.п. против 20-дневной медианы рождает Warning-событие,
      появление дефолта эмитента — Critical с Telegram-алертом.
- [ ] События не спамят: ключи стабильны внутри недели, resolve при нормализации.
- [ ] `scripts/pre-push-check.sh --all` — зелёный.
