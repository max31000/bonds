## Проблема

`GET /api/analytics/replacement-candidates?mode=market` сортирует кандидатов по **сырой
YieldFraction по всему рынку** (`ReplacementEndpoints.cs` ~482–510): наверху всегда самые
рискованные и самые длинные бумаги, дюрация и налог не учитываются. Аллокация market/recommended
строит пул как топ-200 по той же сырой YTM (`AllocationEndpoints.cs` ~265). При этом фильтр
светофора в блоке 1 «Рекомендаций» — клиентский поверх топ-20: включив «только 🟢», можно
увидеть 0 кандидатов, хотя дальше по рынку они есть (открытый вопрос ревью T-38, BACKLOG).
Серверный `reliability=` в `/replacement-candidates` уже существует.

## Что сделать

### A. Сортировка и сопоставимость в mode=market

1. Ранжировать по **после-налоговой доходности к worst** (консервативно):
   `y_rank = min(yield, yield_to_offer ?? yield) × (1 − 0.13)` — та же налоговая конвенция и
   константа, что в задаче 48 (вынести общий хелпер, не дублировать). `yield_date_type` банка
   (42) показывает, к чему биржа уже считает доходность — использовать для подписи
   «к оферте DD.MM.YYYY / к погашению».
2. Сопоставимость по сроку: по умолчанию кандидаты — из **бакета дюрации позиции ±1 соседний**
   (Маколей, задача 44); параметр `durationScope=bucket|all` (default bucket) — фронт получает
   переключатель «похожий срок / весь рынок». При `all` — текущее поведение (но с новой
   сортировкой).
3. Поля сортировки — в DTO (`afterTaxYieldFraction`, `yieldBasis: "offer"|"maturity"`), чтобы UI
   показывал, по чему отранжировано.

### B. Пул аллокации и recommended

1. `AllocationEndpoints` market/recommended: пул топ-200 — по `y_rank` (после-налоговая к worst)
   вместо сырой YTM; жадный алгоритм и лимиты не менять.
2. Проверить (после задачи 46 уже так): `recommended` исключает только Red/Liquidity-Caution,
   не «дешёвых». Интеграционный тест: дешёвая Green-бумага проходит в recommended-пул.

### C. Серверный фильтр светофора в блоке 1 (закрыть вопрос T-38)

1. Фронт, «Рекомендации» блок 1: фильтр «только 🟢 / 🟢+🟡» передавать серверным параметром
   `reliability=` в `/replacement-candidates` (вместо клиентской фильтрации топ-20); лимит
   остаётся 20 — теперь это топ-20 **среди подходящих по надёжности**.
2. Empty-state: «нет кандидатов с выбранной надёжностью в этом бакете — расширьте до всего
   рынка» (кнопка переключает durationScope).
3. Vitest: параметр уходит в запрос; переключатель бакет/рынок; подпись «к оферте/к погашению».

### Тесты

- Юнит: `y_rank` (эталоны руками: yield 0.22, yield_to_offer 0.18 → ранг по 0.18×0.87);
  сортировка стабильна при null yield_to_offer.
- Интеграционные: mode=market с durationScope=bucket отдаёт только соседние бакеты;
  reliability=GREEN серверно сокращает выдачу; recommended-пул отсортирован по after-tax.

## Критерии приёмки

- [ ] Топ кандидатов — сопоставимые по сроку бумаги с лучшей после-налоговой доходностью к
      worst, а не самые длинные/рискованные.
- [ ] «Только 🟢» в блоке 1 даёт серверный топ-20 зелёных (не 0 из клиентской выборки).
- [ ] У каждого кандидата подписано, к чему считана доходность (оферта/погашение) и что налог
      учтён.
- [ ] `scripts/pre-push-check.sh --all` — зелёный.
