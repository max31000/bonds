# Задача 66 — Исполнитель планов во Freedom (выключен по умолчанию)

> **Кому адресовано.** `bond-implementer`. Контекст: дизайн §5, задача 65 (исполнитель T-Invest) — та же архитектура.
>
> **Зависимости:** 65.
>
> **Рамки:**
> - Те же ворота, что в 65: env `Execution__Enabled`, `execution_mode=live`, пауза.
> - Плюс **отдельный** торговый ключ Freedom: провайдер `freedom_trade`. Ключ на чтение `freedom` продолжает служить синку.
> - Freedom-автоисполнение запрещено всегда: `FreedomAutoUsd = 0`. Только планы `Approved` вручную.

---

## Факты (проверено на живом счёте 22–23.10.2026)

- **Заявка.** `putTradeOrder` `{instr_name, action_id: 1 buy | 3 sell (2/4 — маржинальные, ЗАПРЕЩЕНЫ), order_type_id: 2 limit, qty, limit_price, expiration_id: 1 day}`.
  - Ответ: `{order_id, order:{...}}`.
  - Ошибка: `{error: "...", code}` — например, «The instrument is not available for trading.» для `.ITS`.
- **Отмена** — `delTradeOrder {order_id}`.
- **Активные заявки** — `getNotifyOrderJson {active_only:1}`.
- **Торговать только `.US`/`.EU`.** Брокер сам направляет `.US` на ITS, если там есть двойник.
- Комиссию проверять по `getUserCashFlows` (`commission_for_trades`, `(Trade N buy TICKER)`). Маршрут и класс указаны в строке комментария.
- `user_order_id` (кастомный id) поддерживается SDK. Им пользуемся для идемпотентности: сохраняем до отправки, после рестарта ищем заявку по нему в `getNotifyOrderJson`.
- Исполнения по одной заявке приходят несколькими сделками: фикс $1.2 списывается один раз на заявку.

## Что сделать

1. **Провайдер `freedom_trade`** (поля `publicKey`, `privateKey`) с валидатором: `GetAllUserTexInfo` с этим ключом должен вернуть тот же `trader_systems_id`, что ключ на чтение.
   - Право торговать проверить без реальной заявки нельзя. Поэтому в UI честная пометка: «торговое право проверится на первой заявке».
2. **`IFreedomOrderGateway`** — единственное место, где вызываются `putTradeOrder` и `delTradeOrder`.
   - Только `action_id` 1 и 3. Массив разрешённых значений лежит в коде, тест проверяет, что 2 и 4 не отправляются никогда.
3. **`PlanExecutor`** расширяется на Freedom:
   - предполётные проверки как в 65 (котировка, дрейф цены, деньги в валюте строки, `.ITS` запрещён, часы торгов);
   - перевыставление, отмена в конце сессии;
   - сверка комиссии с `FreedomFeeModel` по фактическому маршруту из комментария cashflow.
4. **Архитектурный тест:** вызовы `putTradeOrder`/`delTradeOrder` есть только в `Execution/FreedomOrderGateway.cs`.
5. **Тесты:**
   - fake HTTP (фикстуры `putTradeOrder.json` и `putTradeOrder_error.json` уже лежат в репо);
   - идемпотентность по `user_order_id`;
   - запрет маржинальных `action_id`;
   - запрет `.ITS`;
   - разбор ошибки брокера;
   - сверка комиссии.
   - Песочницы у Freedom нет. Боевую проверку делает владелец одной минимальной заявкой — инструкция в отчёте.

## Критерии приёмки

- [ ] Без всех ворот заявка не уходит (тест).
- [ ] Маржа и `.ITS` невозможны (тест).
- [ ] pre-push-check зелёный.
